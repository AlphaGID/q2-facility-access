# AI assistance disclosure

AI assistance (Claude, Anthropic) was used throughout the development of this
submission. This file states what it was used for, specifically, rather than
as a general disclosure.

## What AI assistance was used for
- Code scaffolding for individual pipeline stages (src/reconcile_crosswalk.py,
  src/clean_facilities.py, src/ingest_scores.py, src/build_database.py,
  src/compute_access.py, src/ward_gap_analysis.py, src/make_outputs.py),
  written iteratively and tested against the actual supplied data at each step.
- Debugging specific failures encountered during development (e.g. the
  DuckDB ALTER TABLE / RTree indexing version issue described in the README
  and in outputs/logs/).
- Drafting documentation: this README, the Technical Defense Document, and
  the one-page methodological note, based on the actual findings, decisions,
  and numbers produced by running the pipeline against the real data — not
  generated independently of the analysis.
- Reasoning through design trade-offs (CRS choice, access-measure choice,
  database engine choice) collaboratively, with every empirical claim in the
  final write-up (error percentages, facility counts, coordinate mismatches)
  verified by actually running the relevant check against the data, not
  asserted from general knowledge.

## What AI assistance was not used for
- No finding, count, or defect described in this repository was invented or
  estimated by AI; every number in the README, defense document, and logs was
  produced by running code against the supplied data and confirmed before
  being written down.
- All final methodological decisions (CRS, access measure, thresholds,
  database engine) were made and are defensible by the candidate, not simply
  accepted from a suggestion.

## Verification
Every claim in this repository's documentation can be independently
regenerated by running `python src/pipeline.py` against the supplied raw data
and comparing the output to outputs/logs/, outputs/tables/, and
data/processed/.
